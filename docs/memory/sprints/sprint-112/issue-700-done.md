## Signaux mémoire
- [MEMORY:pitfall] Context: #700, tiroirs Radix contrôlés (`open`) sans `Dialog.Trigger`. Solution: `DialogContent` modal (Radix Dialog 1.1.6, `dist/index.mjs:144-147`) annule TOUJOURS `onCloseAutoFocus` et focalise `triggerRef` — nul sans Trigger — donc ne rend le focus à RIEN (il tombe sur `body`) ; ce n'est PAS le `FocusScope` nu qui rend le focus à l'élément actif à l'ouverture. Prevention: tout dialogue contrôlé place lui-même le focus dans `onCloseAutoFocus` (`preventDefault` + `ref.focus()`), et le vérifie en E2E réel ; un mock de tiroir qui « rejoue Radix » doit être relu contre `node_modules`, pas contre la doc.
- [MEMORY:pitfall] Context: #700, le test unitaire à tiroir mocké du S90 était vert sur un comportement faux. Solution: le mock refocalisait l'élément actif à l'ouverture quand l'événement n'était pas annulé — hypothèse du composant recopiée dans le mock. Prevention: un mock qui simule une bibliothèque tierce cite la ligne source qu'il reproduit ; sinon il valide l'hypothèse au lieu de la tester (famille PIT-S94-001).
- [MEMORY:pattern] Problem: E2E d'un état intermédiaire pendant un rechargement lent (course contre une temporisation). Solution: stub `page.route` à phases (`empty` → `[]`, `network` → `continue`, `gated` → retient jusqu'à `release()`), promesse `held` pour savoir que la requête est retenue ; `afterEach` : `release()` PUIS `unrouteAll({ behavior: 'wait' })`. Anti-pattern: `setTimeout(1500)` dans le gestionnaire (état intermédiaire non garanti, gestionnaire qui survit au test).
- [MEMORY:pattern] Problem: purger des entités créées À LA SOURIS (pas par `seedProduct`). Solution: `page.on('response')` sur les POST 201 → promesses d'entrées ; `afterEach` inconditionnel → `trackSeed` ; la fixture auto de `support/fixtures.ts` purge ensuite (elle s'exécute après les hooks). Anti-pattern: `trackSeed` en fin de corps de test (sauté si le test rougit).
