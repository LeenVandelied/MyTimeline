## Résumé

**Requête retenue** — UNE native groupée, scopée au caller, dans `ProductRepositoryJpaImpl.countByCategoryForUser` :
`SELECT category_id, count(*) FILTER (WHERE archived = false), count(*) FILTER (WHERE archived = true) FROM products WHERE user_id = :uid GROUP BY category_id`.
Natif obligatoire (PIT-S79-006) : `@SQLRestriction("archived = false")` masquerait les archivés d'un comptage JPQL, et ce sont eux qu'on veut distinguer ; contrepartie, le natif ne filtre rien seul, `user_id` et la séparation actifs/archivés sont posés à la main. Le `WHERE user_id` **n'est pas une optimisation** : les catégories système (owner NULL) sont partagées entre tous les comptes, sans lui la carte publierait le nombre de produits d'autrui. `countByCategoryId` (tous utilisateurs, arme le 409 / protège la FK) est **inchangé** ; un test les oppose explicitement pour qu'aucune refonte ne remplace l'un par l'autre. Une catégorie sans aucun produit du caller est ABSENTE de la map (pas de ligne à grouper) → l'appelant substitue `CategoryProductCounts.EMPTY`.

**Hexagonal** — le port `ProductRepository` rend `Map<UUID, CategoryProductCounts>` où `CategoryProductCounts` est un **record domaine** (`domain/models/`, Java pur, `active`/`archived`/`total()`), jamais l'`Object[]` de la projection native ; la lecture du `category_id` est défensive (`UUID` ou `String`) plutôt qu'un cast. Le port `CategoryService` gagne `getProductCountsForOwner(callerId)` ; le contrôleur zippe. `ArchitectureTest` vert sans dégel.

**Contrat DTO / Zod** — `CategoryResponse` gagne `Integer productCount` et `Integer archivedProductCount`, **annotés `@JsonInclude(NON_NULL)` au niveau CHAMP** (pas au niveau classe : un `NON_NULL` global aurait aussi retiré `color`/`description` nuls et changé le contrat existant). Deux fabriques : `fromDomain(category)` (POST / GET `{id}` / PATCH → champs **absents du JSON**) et `fromDomain(category, counts)` (listing). **Décision** : absence plutôt que `0`, parce qu'un `0` sur une route qui ne sait pas compter est indistinguable d'une catégorie réellement vide — c'est exactement le mensonge que l'issue corrige, il serait rouvert par la première carte peinte sur une réponse de PATCH. Côté Zod : `.optional()`, **jamais** `.nullable()` (le backend n'émet jamais `null` ici).

**Libellés et clés i18n** — arbitrage dev appliqué tel quel : badge coloré `categories-count-{id}` = **actifs** (inchangé, clé `products.categories.productCount`), nœud **frère** hors badge = **archivés**, nouvelle clé plurielle `products.categories.archivedCount` dans les 4 locales (fr `{count, plural, one {# archivé} other {# archivés}}`, en `# archived`, de `# archiviert`, es `# archivado(s)`). Logique : badge masqué si 0 actif **et** ≥ 1 archivé ; « aucun produit » seulement à 0/0. Deux compteurs ⇒ conditionnel JSX, l'ICU d'une seule clé ne peut pas exprimer la combinaison. `productCount` inchangé.

**Testids** — nouveau : `categories-archived-count-{id}` (`text-ink-muted text-2xs`, motif `ProductsListView.tsx:349`). `categories-count-{id}` conservé mais **conditionnel** — c'est le seul changement de contrat pour les specs existantes.

**`linkedProductsCount`** — drawer et dialog reçoivent désormais **actifs + archivés** (`linkedCountOf`), soit le total qui arme réellement le 409 backend : le select de réassignation apparaît d'emblée. Le repli `reassignRequiredByServer` (`DeleteConfirmDialog.tsx`) est **conservé** comme défense quand la carte est périmée, et les deux commentaires qui décrivaient l'ancienne source (« les appelants dérivent d'un listing SANS archivés ») sont réécrits.

## Signaux mémoire

- [MEMORY:business-rule] BR-CAT-008 (#695) — Les compteurs de la carte catégorie sont SERVIS PAR L'API (`GET /api/categories` → `productCount` / `archivedProductCount`), scopés au caller, actifs et archivés SÉPARÉS. « aucun produit » n'est affichable qu'à 0/0. Deux compteurs et non un total : un produit archivé occupe sa catégorie sans être visible des listes, les fusionner ferait mentir l'un des deux écrans. `countByCategoryId` (tous utilisateurs, arme le 409 / la FK) reste distinct et inchangé.
- [MEMORY:decision] Un compteur qu'une route ne sait pas calculer est ABSENT du JSON, jamais `0` — `Integer` + `@JsonInclude(NON_NULL)` au niveau CHAMP, `.optional()` côté Zod. Motif : sur POST/PATCH/GET `{id}`, un `0` est indistinguable d'une catégorie réellement vide ; il suffirait qu'une surface peigne une carte sur une réponse de PATCH pour rouvrir exactement le bug #695. L'annotation est posée au niveau champ et NON classe : un `NON_NULL` global aurait aussi fait disparaître `color`/`description` nuls et changé le contrat existant sans le dire.
- [MEMORY:pattern] Une requête native de comptage par parent se fait en UNE requête groupée (`count(*) FILTER (WHERE …) … GROUP BY parent_id`) rendue en `Map<UUID, RecordDomaine>`, jamais un comptage par ligne affichée (N+1 proportionnel à la page) ni un `Object[]` remonté dans le port. Anti-pattern : exposer la projection JPA brute dans `domain/ports/` — ArchitectureTest ne l'attrape pas toujours, mais la dette est réelle.
- [MEMORY:pitfall] Sur une entité PARTAGÉE entre utilisateurs (ici les catégories « système », owner NULL), un comptage d'entités liées DOIT porter `WHERE user_id = :caller` : sans lui, une simple carte publie le nombre de produits d'autres comptes. Le filtre ressemble à une optimisation et se fait supprimer comme telle en revue de perf — c'est un contrôle d'isolation. Corollaire : deux comptages de la même table peuvent avoir des scopes VOLONTAIREMENT différents (`countByCategoryForUser` = affichage scopé ; `countByCategoryId` = intégrité FK, tous utilisateurs) ; les unifier casse soit l'isolation, soit la FK. Un test qui les OPPOSE explicitement est le seul garde-fou.
- [MEMORY:pitfall] Corriger la source d'un compteur périme les tests E2E qui exerçaient un chemin d'erreur DÉCLENCHÉ par sa fausseté. Ici, le test #546 passait par le 409 uniquement parce que `linkedProductsCount` valait 0 à tort ; le compteur réparé, le select s'arme d'emblée et le repli serveur n'est plus exercé — la couverture disparaît en silence, avec un test qui reste VERT. Reprovoquer le chemin autrement (carte rendue avant l'arrivée du produit) plutôt que supprimer le test ou affaiblir le correctif.
- [MEMORY:pattern] Deux compteurs affichés ensemble ne se modélisent pas par une clé ICU : `{count, plural, …}` ne porte qu'un argument de pluriel. Deux clés + conditionnel JSX, et deux nœuds frères — la concaténation dans un même badge coloré donne aussi une emphase fausse aux archivés (revue Designer #695).
- [MEMORY:pitfall] Une JSDoc qui documente une ABSENCE (« `categories.all` ne porte pas de compteur ») devient fausse silencieusement dès qu'on ajoute ce qu'elle disait absent — et elle sert alors d'argument pour NE PAS invalider. Chercher ces négations dans les hooks voisins avant d'ajouter un champ à un DTO de lecture.
